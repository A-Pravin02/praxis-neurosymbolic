# Reproducing the paper

## Where each part of the paper is implemented

The paper describes a system; this is where that system is. Every row is code in this
repository, not a description of it.

| Paper | What it claims | Code |
|---|---|---|
| Fig. 1 | the architecture diagram itself | `scripts/make_architecture_figure.py` — drawn in matplotlib, no external tool |
| Fig. 2 | the baseline comparison | `scripts/make_results_figure.py` — reads the test-split report |
| IV-A, box A1 | a 33M encoder maps the question to a goal, records and stated facts | `backend/app/neural/query_understanding.py`, `backend/app/neural/encoder.py`, `backend/app/hybrid/router.py` |
| IV-A | the model used as a semantic parser instead | `backend/app/neural/semantic_parser.py` |
| IV-A, box A2 | authorization-filtered retrieval | `backend/app/neural/retrieval.py`, `_retrieve` in `backend/app/evaluation/ns_benchmark.py` |
| IV-B, box B1 | the policy version in force on the case's own date | `_resolve_version` in `backend/app/symbolic/reasoner.py` |
| IV-B, box B2 | records restricted to what the asker may see, **before** reasoning | `backend/app/hybrid/grounding.py`, `backend/app/policy/pdp.py`, `backend/app/policy/service.py` |
| IV-B, box B3 | Kleene three-valued evaluation — unknown is not false | `backend/app/symbolic/engine.py`, `backend/app/symbolic/reasoner.py` (`SATISFIED`, `VIOLATED`, `UNKNOWN`) |
| IV-B | the rule language the policies are written in | `backend/app/symbolic/dsl.py`, `backend/data/meridian/rules/*.rules` |
| IV-C, box C1 | a model may phrase the conclusion, never establish it | `backend/app/neural/response_generation.py` |
| IV-C, box C2 | claims extracted from the wording | `backend/app/hybrid/claims.py` |
| IV-C, box C3 | the 12 checks, four-valued | `Verifier` in `backend/app/hybrid/verification.py`; the census is `scripts/count_checks.py` |
| IV-C, box C4 | the release gate | `backend/app/hybrid/controller.py` |
| IV-D | the worked trace of one question | generated by `worked_trace()` in `scripts/build_paper_docx.py` from the stored records |
| V | world generation, question templates, gold answers | `backend/app/evaluation/worlds.py`, `casegen.py`, `oracle.py` |
| V | the baselines, their prompts and their refusal options | `backend/app/evaluation/ns_benchmark.py`, `backend/app/evaluation/systems.py` |
| VI | the metric definitions | `backend/app/evaluation/research.py`; recomputed independently by `scripts/independent_metrics.py` |
| VIII | the seven ablation switches | `backend/app/hybrid/ablations.py`; that each switch really removes its mechanism is tested in `backend/tests/test_ablation_reach.py` |
| X | the not-covered failure, and five refuted attempts to fix it | `docs/AUDIT.md`, `scripts/probes/` |
| XI | Study II: training, claim extraction, verification | `scripts/prepare_football.py`, `scripts/train_slm.py`, `scripts/run_football_experiment.py` |

The statistics the paper reports that are not read from a report file — the exact
McNemar test, the two-sided Fisher exact test, and the paired bootstrap intervals — are
written out in `scripts/build_paper_docx.py` with no SciPy dependency, and checked
against independently computed values in `backend/tests/test_paper_build.py`.


Every number in `main.tex` is regenerated by the commands below, from committed inputs.
Nothing is copied by hand: runs append per-question rows, `research_report.py` recomputes
every metric from those rows, and `make_figures.py` renders every figure and table from
the report.

(`test_the_frozen_test_split_is_committed_and_unchanged_by_regeneration`) fails if the
generator no longer reproduces the committed test split.

## 1. Validity of the gold answers

```bash
python scripts/check_oracle.py --json backend/data/benchmark_worlds/oracle_check.json
```

Expected: `ALL 3914 / 3914` agreement and `killed 12 / 12 mutants`. The script exits
non-zero on any disagreement or surviving mutant.

## 2. A language model

The model-based systems reach an open-weights model through a local OpenAI-compatible
server (needs CUDA PyTorch and `transformers`; `bitsandbytes` for `--4bit`):

```bash
python scripts/local_llm_server.py --model <path>/Qwen2.5-1.5B-Instruct
```

Every completion is cached in `eval_reports/llm_cache/<model>.sqlite`, keyed by the exact
messages and token limit; a re-run is served from the cache and reproduces the answers
exactly. The cache is the record of the raw model outputs the results were scored on.

## 3. Runs

Systems without a model (tag `deterministic`):

```bash
python scripts/run_research.py --split test --tag deterministic \
  --systems neurosymbolic neurosymbolic_lexical rag_extractive
```

Model-based systems, one tag per model:

```bash
LLM_PROVIDER=openai LLM_BASE_URL=http://127.0.0.1:8765/v1 LLM_MODEL=Qwen2.5-1.5B-Instruct \
LLM_TIMEOUT_SECONDS=900 python scripts/run_research.py --split test --tag qwen2.5-1.5b --workers 12 \
  --systems llm_only llm_rag llm_rag_selfcheck llm_rag_rules ns_parser ns_parser_llm \
            ns_parser_no_verification ns_parser_latest_version ns_parser_two_valued \
            ns_parser_trust_statements ns_parser_no_authorization
```

Runs are resumable: an interrupted run continues from the rows already written to
`eval_reports/research/<tag>/<split>.<system>.jsonl`.

## 4. Report, figures, tables

```bash
python scripts/research_report.py --split test      # docs/paper/results/test.json
python scripts/make_figures.py --split test         # docs/paper/figures/*
```

Only complete runs (every question of the split answered) are included in the report.

## 5. The paper

The submitted artifact is `docs/paper/PRAXIS_IEEE.docx`, built from the result files by
`scripts/build_paper_docx.py`; `main.tex` is an earlier LaTeX draft and is **not** what
the PDF is made from.

```bash
pip install -r backend/requirements-paper.txt
python scripts/build_paper.py --pdf
```

That is the whole build. It runs seven stages in order and stops at the first that
fails: input check, Fig. 1 (with its own type-size and placement audit), Fig. 2, the
document, the PDF export, the claim check against the built document, and the
independent recomputation of every metric. `--check-only` verifies the inputs and
writes nothing. Each stage is also a script that runs on its own:

```bash
python scripts/check_paper.py                        # inputs, and every figure's source
python scripts/make_architecture_figure.py --audit   # Fig. 1
python scripts/make_results_figure.py                # Fig. 2
python scripts/build_paper_docx.py \
  --template docs/paper/templates/ieee_a4_transitional.docx \
  --out docs/paper/PRAXIS_IEEE.docx
powershell -File scripts/export_pdf.ps1 docs/paper/PRAXIS_IEEE.docx   # Windows + Word
```

Both figures are **matplotlib code in this repository**, not images drawn elsewhere and
checked in: `backend/tests/test_paper_build.py` regenerates each one and compares it
byte for byte with the committed file, so a figure that was edited by hand fails the
suite. The PNGs were drawn with the matplotlib pinned in
`backend/requirements-paper.txt`; on a different version that test skips with a note
rather than failing, because matplotlib's output moves between releases.

The build refuses to emit a placeholder for a missing result file, and it fails if the
case the Section IV-D trace quotes stops demonstrating the policy-version reversal it
is quoted for.

PDF export drives Microsoft Word through COM, so it needs Windows. The `.docx` is the
artifact and builds anywhere; the PDF is a rendering of it.

## Protocol notes

- Development questions were used to find and fix faults in the system. Test questions
  were not inspected for that purpose, and every system change after the test split was
  frozen is in the git history.
- Decoding is greedy. Requests are batched on the GPU; batching can rarely change a greedy
  token through floating-point noise, which is why the completion cache, not re-generation,
  is the reference for reported numbers.
- Bibliographic entries in `references.bib` were entered from memory and must be checked
  against publisher records before submission.

## Latency: what the reported figures measure

The paper is exactly six pages and the column holding the experimental design has no
slack, so the protocol is stated here. Table II's latency column is the **per-question
mean of wall-clock time inside the system under test**. It excludes process start-up,
model download and knowledge-pack loading. It *includes* the first question of each
world, which also builds that world's goal catalogue and policy index, and that question
costs several times any other.

The PRAXIS rows run entirely on CPU: the encoder is bge-small through ONNX Runtime and
nothing else in the decision path is a model. The language-model rows are not
comparable hardware: their time is spent waiting on `local_llm_server.py`, which
generates on whatever device it was started with. **That device, and whether the 7B was
loaded in 4-bit, are not recorded in the run metadata**, so the LLM latencies should be
read as "seconds, not milliseconds" rather than as a hardware-controlled measurement.
The two-orders-of-magnitude gap the paper claims does not depend on the difference:
the PRAXIS figures are CPU-only, so a faster device for the baselines would narrow it
but the CPU-only path would still be the cheap one.

Three figures in the artifacts measure three different things, and they are easy to
mistake for each other:

| Figure | What it is |
|---|---|
| 77.9 ms | Table II, LLM-free. Mean over 255 questions, measured during a run of all 14 systems. Median 61.3 ms; the slowest case is 1421 ms, the first question of world 101. |
| 46.6 ms | The same system re-run alone with `--workers 1` (`eval_reports/research/latency-protocol/`). Accuracy and hallucination reproduce exactly at 0.796 and 0.149; only latency moves, because the published run shared a machine with the language-model systems. The published figure is therefore the conservative one. |
| 146 ms / 3.2 ms | The ten demo cases, first pass and repeat (`artifacts/demo_suite.json`). The encoder memoises embeddings by text, so asking the same question twice in one process is about forty times cheaper. Only the first pass is comparable to the two figures above. |

Regenerate the last of these with `python scripts/record_demo_suite.py`, which records
both passes and labels which is which.

## Models and inference stacks, per configuration

Reported separately because the paper's capability limitation turns on it: the 1.5B and
7B results do not share an inference stack, so a difference between them is not purely a
difference of model size.

| Configuration | Model | Role | Inference stack |
|---|---|---|---|
| PRAXIS (default, "LLM-free") | none on the decision path | — | deterministic realizer; bge-small 33M encoder via ONNX, CPU |
| PRAXIS + parser | Qwen2.5-7B-Instruct | semantic parser only; decisions stay symbolic | `scripts/local_llm_server.py`: torch + transformers behind an OpenAI-compatible HTTP API, greedy, with an SQLite completion cache keyed by (model, messages, max_tokens) |
| `llm_only`, `llm_rag`, `llm_rag_rules`, `llm_rag_selfcheck` | Qwen2.5-7B-Instruct | answers the question | same server as above, so every system reaches the model through one API |
| Scale comparison, Section XII | Qwen2.5-1.5B-Instruct | same roles as the 7B | Hugging Face `transformers`, greedy, CPU/CUDA (`LocalTransformersProvider`) |
| Relevance-gate measurement | Qwen2.5-1.5B-Instruct | semantic parser | `transformers`, as above |
| Study II | nanoGPT, 4.3M parameters (4 layers, 4 heads, width 256, vocabulary 4096), trained from scratch on 292,948 tokens | generator under the gate | project code, see Section XI |

Decoding is greedy everywhere and temperature is 0.

## Independent re-verification

These commands were run and their results are what the paper and the change log report.
A reviewer re-running them is re-verifying, not taking the report's word:

```bash
python scripts/independent_metrics.py    # 151 values from raw records, 0 mismatched
python scripts/verify_claims.py          # 26 textual claims against the artifacts
python scripts/check_paper.py            # build inputs, and every figure's source script
cd backend && python -m pytest tests/ -m no_db -q    # 160 passed
cd backend && python -m pytest tests/test_paper_build.py -q   # 17 passed
powershell -File scripts/export_pdf.ps1 docs/paper/PRAXIS_IEEE.docx   # 8 pages
```

The paper was six pages before the reviewer's additions — the baselines paragraph, the
dataset and rule-base sizes, the code link, the worked trace, the full confirmatory
table and the extra columns in the ablation table — and is eight with them. If the venue
enforces six, the content has to come back out; it is not a layout problem.
